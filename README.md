# VeriFact AI

### An Explainable, Evidence-Grounded and Adaptive Hallucination Detection Framework for Large Language Models

## 1. Project Overview

VeriFact AI is an integrated framework designed to identify and analyse potentially hallucinated information in responses generated by Large Language Models (LLMs).

The system aims to improve the reliability and transparency of LLM-generated answers by combining:

- Multiple independent response generation.
- Atomic factual claim extraction.
- Self-consistency-based hallucination detection.
- Semantic similarity analysis.
- External evidence retrieval and verification.
- Natural Language Inference (NLI).
- Explainable claim-level verification results.
- Adaptive evidence retrieval.
- Interactive Streamlit dashboard.

The project builds upon ideas introduced in **SelfCheckGPT (Manakul et al., EMNLP 2023)** and extends the workflow through claim-level analysis, external evidence verification, adaptive retrieval, and explanations.

**Important:** Consistency between multiple generated answers does not guarantee factual correctness. A claim repeated consistently can still be false. Therefore, consistency analysis and external evidence verification are treated as separate components.

---

## 2. Project Objectives

1. Generate an original LLM response for a user-provided question.
2. Generate multiple independent responses to the same question.
3. Extract atomic factual claims from generated answers.
4. Identify inconsistencies between independently generated responses.
5. Retrieve relevant external evidence for extracted claims.
6. Analyse evidence using Natural Language Inference.
7. Classify claims as supported, contradicted, or insufficiently supported.
8. Generate understandable explanations for verification results.
9. Implement adaptive evidence retrieval to gather additional context when necessary.
10. Integrate all components into an interactive dashboard.

## 3. Team Contributions

The project is divided into three integrated implementation components.

### Person 1 – Answer Generation and Claim Extraction

**Primary responsibility:** Generate AI responses and convert them into structured factual claims.

Main components:

- Gemini API integration.
- Original answer generation.
- Independent response generation.
- Sentence segmentation using spaCy.
- Atomic factual claim extraction.
- Named entity extraction.
- Claim formatting and unique claim ID assignment.
- Structured JSON output.

Main directories:

- `generation/`
- `claim_extraction/`

### Person 2 – Hallucination and Consistency Detection

**Primary responsibility:** Identify potentially inconsistent or suspicious claims by comparing the original answer with independently generated responses.

Implemented techniques:

**1. SelfCheck Baseline**
- Compares original claims with independent response samples.
- Uses word-level Jaccard similarity.
- Identifies possible inconsistencies.

**2. BERTScore**
- Measures semantic similarity between claims and generated samples.
- Calculates average similarity and disagreement.

**3. NLI Detection**
- Analyses entailment, contradiction, and neutral relationships.
- Uses the `cross-encoder/nli-deberta-v3-small` model.
- Provides additional diagnostic signals.

**4. Combined Scoring Engine**

Default scoring weights:

| Detector | Weight |
|---|---:|
| SelfCheck | 50% |
| BERTScore | 50% |
| NLI | 0% |

NLI is retained as a diagnostic component but excluded from the default combined risk score because its neutral-class performance was insufficient in the initial manually labelled evaluation.

The combined risk score is experimental and is not a calibrated probability of hallucination.

Main directory:

- `hallucination_detection/`

Additional documentation:

- `docs/PERSON2_EVALUATION.md`

### Person 3 – Evidence Verification and Dashboard Integration

**Primary responsibility:** Retrieve external evidence, verify claims, generate explanations, and integrate the verification workflow into the dashboard.

**1. Evidence Retrieval**
- Wikipedia API integration.
- Query expansion.
- Relevant passage extraction.
- Caching and retry handling.
- Duplicate evidence removal.

**2. Evidence Ranking**
- TF-IDF and cosine similarity.
- Relevance-based passage ranking.
- Evidence diversity handling.

**3. Evidence-Based NLI Verification**
- Uses `cross-encoder/nli-deberta-v3-small`.
- Analyses entailment, contradiction, and neutral relationships.
- Considers evidence diversity and configured confidence thresholds.
- Generates verification verdicts.

Implemented verdict categories:

- `supported`
- `contradicted`
- `insufficient_evidence`

**4. Adaptive Evidence Verification**

The adaptive verifier follows this workflow:

1. Retrieves an initial set of 5 evidence passages.
2. Ranks the passages and selects the top 3.
3. Performs initial NLI verification.
4. Checks whether the result requires additional evidence.
5. If necessary, retrieves an expanded set of 10 passages.
6. Selects the top 8 ranked passages.
7. Combines and deduplicates the evidence.
8. Performs final verification.

**5. Claim Explanation**
- Generates explanations based on verification results.
- Helps users understand the reasoning behind each verdict.

**6. Dashboard Integration**
- Integrates the complete workflow into Streamlit.
- Displays claim-level evidence and verification results.
- Supports Live Mode and Demo Mode.

Main directories:

- `evidence_retrieval/`
- `explanation/`

Main dashboard:

- `app_test.py`

## 4. System Architecture

VeriFact AI combines answer generation, consistency analysis, and external evidence verification into an integrated workflow.

```text
              USER QUESTION
                    |
                    v
          PERSON 1: GENERATION
                    |
          +---------+---------+
          |                   |
          v                   v
    Original Answer     Independent Samples
          |                   |
          +---------+---------+
                    |
                    v
             CLAIM EXTRACTION
                    |
                    v
             ATOMIC CLAIMS
                    |
          +---------+---------+
          |                   |
          v                   v
     PERSON 2             PERSON 3
 CONSISTENCY ANALYSIS   EVIDENCE RETRIEVAL
          |                   |
          v                   v
  SelfCheck/BERTScore    Evidence Ranking
          |                   |
          v                   v
   Experimental Risk    Evidence-Based NLI
          |                   |
          |                   v
          |             Adaptive Retrieval
          |                   |
          |                   v
          |             Final Verification
          |                   |
          |                   v
          |             Claim Explanation
```

Person 2 and Person 3 provide complementary analysis:

- Person 2 evaluates consistency across independently generated responses.
- Person 3 evaluates claims against retrieved external evidence.

The final dashboard presents these results together to help users analyse potentially hallucinated information.

## 7. Dashboard

VeriFact AI provides an interactive Streamlit dashboard with two execution modes.

### 7.1 Live Mode

Live Mode executes the complete workflow using a newly generated AI response.

Workflow:

1. Accepts a user question.
2. Generates an original answer using Gemini.
3. Generates independent response samples.
4. Extracts factual claims.
5. Performs consistency and hallucination analysis.
6. Retrieves external evidence.
7. Performs evidence-based verification.
8. Displays claim-level results and explanations.

### 7.2 Demo Mode

Demo Mode uses saved demonstration data to execute the verification workflow without generating a new Gemini response.

It allows users to explore the project functionality without requiring a new LLM API request.

### 7.3 Dashboard Features

The dashboard includes:

- User question input.
- Original AI-generated answer.
- Independent response analysis.
- Extracted factual claims.
- Claim-level consistency scores.
- Experimental hallucination risk score.
- Evidence retrieval results.
- Entailment, contradiction, and neutral counts.
- Verification verdicts.
- Adaptive retrieval information.
- Evidence-based explanations.
- Overall verification summary.

## 8. Installation and Setup

### Step 1: Clone the Repository

```powershell
git clone https://github.com/A377548/VeriFact-AI.git
cd VeriFact-AI
```

### Step 2: Create a Virtual Environment

```powershell
python -m venv .venv
```

### Step 3: Activate the Virtual Environment

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### Step 4: Install Dependencies

```powershell
pip install -r requirements.txt
```

### Step 5: Configure the Gemini API Key

Create a `.env` file in the project root directory.

Add:

```env
GEMINI_API_KEY=your_actual_api_key
```

The repository provides `.env.example` as a configuration template.

**Security:** Never commit the actual `.env` file or expose API credentials in the repository.

### Step 6: Run the Application

To run the command-line application:

```powershell
python main.py
```

To launch the Streamlit dashboard:

```powershell
python -m streamlit run app_test.py
```

### Step 7: Run Automated Tests

```powershell
python -m pytest tests/ -v
```

## 10. Known Limitations

1. **Limited evidence sources:** The current evidence retrieval implementation primarily relies on Wikipedia.
2. **Retrieval relevance:** TF-IDF and cosine similarity measure textual relevance but do not establish factual support.
3. **NLI limitations:** The NLI model can incorrectly classify evidence, particularly for complex or context-dependent claims.
4. **Source independence:** Multiple articles from the same publisher do not necessarily represent independent confirmation.
5. **Experimental risk scoring:** The combined hallucination risk score is not a calibrated probability.
6. **Evidence availability:** Some claims may not receive enough relevant evidence to produce a reliable verdict.
7. **External API dependencies:** Live Mode depends on Gemini API availability and configuration.
8. **Verification reliability:** Model-assisted verdicts should not be treated as guaranteed factual conclusions.
